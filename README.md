# NetraShield

Privacy-preserving browser vision agent prototype for SIH Problem Statement 26171: "On-device Visual Perception for Light-weight Browser Agents".

## What this prototype demonstrates

- A Chrome/Firefox-style extension popup built with React + Vite.
- A content script that performs local perception over the active page using DOM geometry, semantic labels, field metadata, and regex PII detectors.
- Local redaction boxes for passwords, emails, phone numbers, Aadhaar-like IDs, PAN, UPI IDs, card-like numbers, DOB text, and sensitive form fields.
- A server-safe payload that contains only masked labels, element roles, bounding boxes, redaction metadata, coarse page structure, and timing/resource-oriented metrics.
- A background service worker that sends only the sanitized payload to a reasoning server.
- A small local demo server that returns an action command, which the extension executes by highlighting the target element for user approval.

## Recommended tech stack for the full SIH build

Client extension:

- Browser extension: Manifest V3, content scripts, background service worker.
- UI: React + TypeScript + Vite.
- Local inference: ONNX Runtime Web with WebGPU/WASM fallback, or Transformers.js for smaller browser models.
- Visual detectors: lightweight object/text detector for screenshots, plus DOM-based semantic detectors.
- OCR: local OCR only when needed, preferably behind a strict privacy gate.
- Redaction: canvas-based screenshot masking plus DOM overlay masking.

Server:

- Node/Express or FastAPI for the command API.
- LLM/VLM adapter: local Ollama/Llama.cpp during offline demo, or a hosted model during development.
- Contract: accept only `netrashield.sanitized.v1` payloads, never raw screenshots or raw DOM text by default.

Evaluation:

- Accuracy: compare predicted actionable element and page-state labels against test tasks.
- PII recall/precision: synthetic pages with labeled PII boxes.
- Redaction precision: IoU between expected sensitive boxes and produced boxes.
- Resource use: popup-reported timings plus Chrome Task Manager or Performance panel.
- Latency: local scan time + redaction time + server round trip + action execution time.

## Architecture

```text
Page DOM/screen
  -> content-script local perception
  -> PII/sensitive-region detection
  -> local mask overlay
  -> sanitized payload
  -> background service worker
  -> reasoning server
  -> command
  -> user-visible browser action
```

Raw passwords, raw PII values, and full page text should not be sent to the server. The server receives redaction boxes, masked labels, public element roles, and coarse layout structure.

## Run locally

Install dependencies:

```bash
npm install
```

Build the extension:

```bash
npm run build
```

Start the demo reasoning server:

```bash
npm run server
```

Load extension:

1. Open `chrome://extensions`.
2. Enable Developer mode.
3. Choose "Load unpacked".
4. Select the `dist` folder generated by `npm run build`.
5. Open any normal webpage, refresh it once, then open NetraShield.

Demo flow:

1. Click `Scan`.
2. Click `Mask page` to show local redaction.
3. Inspect the server-safe payload preview.
4. Click `Ask server`.
5. Click `Execute` to highlight the suggested action target.

## Next improvements for finale quality

- Replace the current heuristic local perception layer with a real browser model: MobileViT/DETR/YOLO-NAS-small exported to ONNX, running through ONNX Runtime Web.
- Add local face/person detection for screenshot regions before any visual context leaves the client.
- Add a canvas screenshot sanitizer: draw visible tab screenshot, black out redaction boxes locally, then send only the sanitized image if the task truly needs image context.
- Add an evaluation harness with synthetic pages and labeled expected boxes.
- Add user controls for "never send image", "send sanitized DOM only", and "send sanitized image + DOM".
- Add Firefox compatibility testing and a browser API wrapper if needed.
